# DualShock 4 — виртуальный аудиодрайвер

HAL-плагин CoreAudio, который создаёт в системе устройство **«DualShock 4»**:
звук, записанный в него приложениями, сразу читается как вход. Это loopback
без внешних зависимостей вроде BlackHole.

```
приложения → «DualShock 4» (output) → кольцевой буфер → «DualShock 4» (input)
                                                              ↓
                                                    ds4probe → SBC → DS4
```

## Сборка

```bash
cd tools/ds4driver
./build.sh
```

Результат: `build/DS4AudioDriver.driver` — **universal** (arm64 + x86_64),
macOS 13+.

## Установка

Нужны права администратора — драйвер копируется в системную папку HAL:

```bash
sudo ./install-driver.sh
```

Скрипт сам перезапускает `coreaudiod`. GUI умеет устанавливать драйвер сам:
кнопка «Установить драйвер…» (или мастер настройки при первом запуске)
показывает стандартный диалог пароля macOS.

## Устройство появляется и исчезает вместе с приложением

Драйвер установлен в системе постоянно, но **устройство «DualShock 4» видно
в списке CoreAudio только пока работает приложение**:

```
приложение работает → /var/tmp/com.ds4audio.gui.heartbeat обновляется раз в секунду
                      → драйвер публикует устройство
приложение закрыто  → heartbeat-файл удаляется
                      → драйвер убирает устройство из списка CoreAudio
```

Механизм держит и аварийный случай: если приложение упало и не успело удалить
файл, heartbeat всё равно протухнет через 4 секунды, и устройство исчезнет.

Публикация и снятие делаются через `Plugin::AddDevice` / `Plugin::RemoveDevice`
libASPL — CoreAudio получает уведомление об изменении списка устройств, и
«Настройки звука» сразу показывают правильную картину. Никаких прав root и
перезапусков `coreaudiod` при каждом запуске приложения не нужно.

Путь heartbeat-файла — `kHeartbeatPath` в `Driver.cpp`; он должен совпадать с
`DriverHeartbeat.path` в GUI (`tools/ds4gui/Sources/DS4Audio/DriverHeartbeat.swift`).
В `Info.plist` драйвера он продублирован в ключе `DS4HeartbeatPath`, а ключ
`DS4HideSupportVersion` сообщает GUI, что установленная версия умеет
прятать устройство.

## Удаление

```bash
sudo ./uninstall-driver.sh
```

## Параметры устройства

| Параметр | Значение |
|---|---|
| Имя | `DualShock 4` |
| UID | `com.ds4audio.driver.dualshock4` |
| Производитель | `DS4Audio` |
| Каналы | 2 (стерео) |
| Частота | 48 кГц |
| Формат | Float32, interleaved |
| Транспорт | Virtual |
| Буфер | 2 секунды |

## Зависимости

Драйвер использует [libASPL](https://github.com/gavv/libASPL) (MIT). Копия
библиотеки лежит в `vendor/libASPL`, лицензия — `vendor/libASPL/LICENSE`.

## Ограничения

- Драйвер устанавливается в `/Library/Audio/Plug-Ins/HAL`, то есть действует
  на всю систему и требует администратора.
- При обновлении macOS или пересборке драйвера его нужно установить заново.
- Подпись ad-hoc. Для распространения приложения нужна Developer ID-подпись
  и нотаризация.
- Пока приложение не запущено, устройства «DualShock 4» в системе нет —
  выбрать его выводом нельзя. Это осознанное поведение (см. раздел выше).
