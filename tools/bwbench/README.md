# bwbench — измерение потолка канала macOS → DS4

Все утилиты пишут HID-output-отчёты в DS4 и меряют **время записи**.
Запускать **вне песочницы** (нужен Bluetooth; из sandbox `powerState = 0`).

## Главное правило чтения результатов

```
write_time = ceil((len + 5) / 83) × 15.2 мс
```

Одно окно опроса ≈ 15.2 мс и вмещает **один** ACL-пакет = 5 (L2CAP+HIDP) +
78 (отчёт) байт. Отсюда ступеньки: 78 B → 15 мс, 79 B → 30 мс.

## Инструменты

| Файл | Что делает | Сколько идёт |
|---|---|---|
| **`edge`** | **быстрый тест окна**: пишет 78 B и 79 B, печатает оба времени. Если 79 заметно дороже 78 — окно 15 мс. | ~2 с |
| `boundary` | полная граница: длины 60…120 B, таблица мс/отчёт | ~30 с |
| `fill` | таблица упаковки по всем профилям (0x11…0x19) → % реалтайма | ~30 с |
| `bwbench` / `bwbench2` / `bwbench3` | скорость записи для набора длин | ~5 с |
| `bidir` | одновременно вход + выход (проверка независимости бюджетов) | ~10 с |
| `longrun` | длинный прогон на стабильность | минуты |
| `bwproc` | несколько процессов параллельно | ~10 с |
| `sweep` / `small` / `pkttype` / `combo` / `dualdev` | эксперименты, давшие отрицательный результат | — |

## Типовой сценарий

```bash
cd tools/bwbench

# 1. Убедиться, что окно всё ещё 15 мс
./edge 40
#   78B: 13.4 мс   79B: 28.5 мс   -> окно ~13.4 мс (1.13 x от 15.2)

# 2. Посмотреть, какому профилю хватает канала
./fill 3
```

## Что уже проверено этими инструментами (и не помогло)

- 1…8 потоков записи, несколько процессов — ровно 5.0–5.1 КБ/с;
- `ReportInterval`, `kIOHIDOptionsTypeSeizeDevice` — без эффекта;
- одновременные вход и выход — **складываются** (5.0 + 5.7 = 10.8 КБ/с),
  значит бюджет привязан к окнам, а не к общему MTU.

Подробности — `notes/THROUGHPUT.md` и `notes/SNIFF-XPC.md`.

## Сборка

```bash
clang -O2 -framework CoreFoundation -framework IOKit edge.c -o edge
clang -O2 -framework CoreFoundation -framework IOKit fill.c -o fill
```
